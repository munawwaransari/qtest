- 1
What relationship is depicted by below?
 +---------+                      +---------+
 | Student | 1 ---------------- M | Subject |
 +---------+                      +---------+
 
I   - One Student entity is related to zero or more Subject entities
II  - One Student entity is related to one or more Subject entities
III - One Subject entity is related to only one Student entity
IV  - One Subject entity is related to zero or one Student entity

[A] I & II
[B] I & III
[C] II & IV
B
~
An ER one-to-many relationship is a link between two entities where one instance of the "one" entity can be associated with zero or more instances of the "many" entity, but each instance of the "many" entity is associated with only one instance of the "one" entity. This is a fundamental concept in database design, often seen in a Customer and Orders relationship, where one customer can have many orders, but each order belongs to only one customer. 
~

[B] one-to-one
[C] many-to-many
[D] many-to-one

~
In an RDBMS, many-to-many relationship is implemented using a relationship table having a composite primary key that references primary keys from both the entities.
~
- 5
Given the basic ER and relational models, which of the following is INCORRECT?

[A] attribute of an entity can have more than one value
[B] In a row of a relational table, an attribute can have more than one value
[C] An attribute of an entity can be composite
[D] In a row of a relational table, an attribute can have exactly one value or a NULL value
B
~
An entity attribute can have multiple values. These are known as multivalued attributes in database management systems (DBMS) and entity-relationship (ER) modeling.

However, an attribute in a table row must hold only a single, atomic value or be NULL; having multiple values in one cell violates this rule, but this is managed by creating a separate table or multiple rows for multivalued attributes like programming languages for a coder. 
~
- 6
Which of these is NOT an advantage of indexing.
[A] Faster Data Retrieval
[B] Efficient Sorting
[C] Efficient Searching
[D] No Maintenance overhead
D
~
When indexes are updated often, this may lead to an increase in maintenance overhead and the need for extra storage.

Other disadvantages of indexing are:

Not Suitable for Big Databases: Performance may suffer if the database is too large or has an excessive number of indexes, which may slow down writes and updates.

Performance Impact on Insertions and Updates: The need to update the indexes after each data insertion, deletion, or update may lead to slower data modification operations.
~
- 7 
Choose incorrect statement about strong and weak entities.
[A] A strong relationship is shown with double diamond in an ER diagram
[B] A strong relationship exists between two strong entities, with both having independent primary keys
[C] A weak relationship involves a weak entity and a strong entity, where the weak entity's existence depends on the strong entity
[D] A weak entity is shown with a double rectangle in an ER diagram
A
~
A strong relationship exists between two strong entities, with both having independent primary keys, and is shown by a single diamond in an ER diagram. A weak relationship, conversely, involves a weak entity and a strong entity, where the weak entity's existence depends on the strong entity. This is represented by a double diamond for the weak relationship, a double rectangle for the weak entity, and a double line connecting it to the strong entity.  
~

Select incorrect statement about below comand?

    CREATE INDEX idx_last_name ON employees (last_name);
	
[A] CREATE INDEX: This is the SQL statement that initiates the creation of an index
[B] idx_last_name: This specifies the column (or columns) that the index will cover
[C] employees: This is the table on which the index is being created
B
~
The given SQL command  is used to create an index on the last_name column of the employees table.

Here is a breakdown of what each part of the command does:
CREATE INDEX: This is the SQL statement that initiates the creation of an index.
idx_last_name: This is the name given to the new index. Naming conventions often use idx_ as a prefix for clarity.
ON employees: This specifies the table on which the index is being created.
(last_name): This specifies the column (or columns) that the index will cover
~
